# New Analysis

This folder is the clean analysis namespace for the DFT/xTB target-design work.
It may read inputs from older project folders, but new tables, plots, manifests,
and reports should use the naming rules below.

## Naming Contract

Do not use the old names `totE` or `delta` in this analysis.

Use these target names:

| Name | Meaning |
| --- | --- |
| `DFT` | raw DFT energy |
| `xTB` | raw xTB energy |
| `DFT_ref` | residual of `DFT` after subtracting the reference correction |
| `xTB_ref` | residual of `xTB` after subtracting the reference correction |
| `DFT_ref,BoE` | residual of `DFT_ref` after subtracting BoE fitted on `DFT_ref` |
| `xTB_ref,BoE` | residual of `xTB_ref` after subtracting BoE fitted on `xTB_ref` |

Here, `BoE` means a composition / bond-order linear reference fitted on the
specified target. For example:

```text
DFT_ref,BoE = DFT_ref - BoE_fit(DFT_ref)
xTB_ref,BoE = xTB_ref - BoE_fit(xTB_ref)
```

When comparing DFT and xTB after the same preprocessing, use math notation in
prose, tables, and figures:

```text
Delta^xTB_ref = DFT_ref - xTB_ref
Delta^xTB_ref,BoE = DFT_ref,BoE - xTB_ref,BoE
```

Here, `xTB` is the superscript because xTB is the baseline being subtracted
from DFT, and `ref` / `ref,BoE` are subscripts because they specify the shared
preprocessing applied before the DFT-minus-xTB difference.

In LaTeX-ready text, write these as:

```tex
\Delta^{\mathrm{xTB}}_{\mathrm{ref}}
\Delta^{\mathrm{xTB}}_{\mathrm{ref,BoE}}
```

For prose, table labels, and plot labels, use the comma notation:

```text
DFT_ref,BoE
xTB_ref,BoE
```

For code identifiers, filenames, and column-safe names, use a hyphen or another
safe ASCII spelling rather than a comma:

```text
DFT_ref-BoE
xTB_ref-BoE
Delta_xTB-ref
Delta_xTB-ref-BoE
```

## Baseline MAE Convention

When discussing in-domain tmQM baseline performance, use validation MAE on the
GemNet validation split, not the full-dataset fitting error. A fair in-domain
baseline MAE means:

```text
fit baseline on neutral tmQM train split only
predict neutral tmQM val split
score against the same target used by GemNet
```

For OOD transfer analyses, use the baseline model fitted on the full neutral
tmQM dataset before applying it to the OOD set. This keeps the in-domain
generalization question separate from the cross-domain transfer question.

## BoE Difference Equivalence Check

The script `prove_boe_difference_equivalence.py` numerically tests:

```text
Delta^xTB_ref,BoE = DFT_ref,BoE - xTB_ref,BoE
```

and compares it with directly fitting BoE on:

```text
Delta^xTB_ref = DFT_ref - xTB_ref
```

Result on the common local tmQM rows:

```text
n_common_rows = 71038

Saved-prediction arithmetic identity:
max abs difference = 9.16e-16

Common-alpha linear Ridge identity:
max abs prediction difference = 7.77e-15
max abs residual difference   = 7.77e-15
```

The old saved `DFT_ref,BoE` and `xTB_ref,BoE` fits used independently selected
RidgeCV alphas:

```text
DFT_ref,BoE alpha = 112.88378916846884
xTB_ref,BoE alpha = 70.17038286703837
```

Therefore, an independently refit BoE model on `Delta^xTB_ref` is exactly
equivalent to the difference of separate fits only when the same rows, features,
standardization, intercept convention, and ridge alpha are used.

Important training note:

```text
New_Analysis/datasets/tmQM__Delta_xTB-ref-BoE.csv
```

stores `Delta_xTB-ref-BoE` as the difference of the two already BoE-removed
targets:

```text
Delta_xTB-ref-BoE = DFT_ref-BoE - xTB_ref-BoE
```

Therefore, the current Trillium GemNet run
`delta_xtb_ref_boe_reproducibility_2026_05` trains on:

```text
(DFT_ref - BoE_fit(DFT_ref)) - (xTB_ref - BoE_fit(xTB_ref))
```

It does not rebuild the target by refitting a new BoE model inside the GemNet
preparation script. The separate equivalence check shows that, for our linear
BoE construction on the common rows, this saved target is numerically equivalent
to:

```text
Delta^xTB_ref - BoE_fit(Delta^xTB_ref)
```
